# Process-state matrix

Setup for the manual tests: install the debug APK, grant permissions (see README), create a schedule
covering "now" for an app such as Chrome, and keep `adb logcat -s Freezr FreezrA11y` open.

| # | State | Implementation | Automated test | Manual test |
|---|---|---|---|---|
| 1 | App UI in foreground | ViewModels expose `StateFlow`s derived from Room/DataStore flows (`FreezeStateRepository.snapshot`, `StrictGuard.locked`). Every repository write calls `RuleChangeNotifier` → `EnforcementCoordinator.replan()` (alarms, service re-evaluation, notification, widget, tiles). | `ViewModelTest`, `RepositoriesTest.every write notifies the planner`, `FreezeStateRepositoryTest` | Edit a schedule to start 1 min from now; the home hero and `adb shell dumpsys alarm \| grep freezr` update immediately. |
| 2 | App in background | Enforcement runs only in `FreezrAccessibilityService` against the cached snapshot. No Activity/ViewModel is involved. | — (service) | Press Home, open the frozen app → overlay within ~300 ms. |
| 3 | Process killed | The accessibility service is system-bound; Android restarts the process. `onServiceConnected` → `reconcileAll()` (whitelist, usage reconcile, geofences, Wi-Fi, housekeeping) → `replan()` (alarms) → window scan → `reevaluate()`. Quick Freeze, passes, limits are absolute timestamps in Room. | `ProcessStateTest.a new process rebuilds the same plan`, `FreezeStateRepositoryTest.fresh repository rebuilds identical context` | `adb shell am kill com.freezr.app` (background) and `adb shell run-as com.freezr.app kill -9 $(adb shell pidof com.freezr.app)`; open the frozen app → still frozen; `pidof` shows a new PID. *(Verified on an API 36 emulator.)* |
| 4 | Device reboot | `LockedBootReceiver` (direct-boot aware) re-arms alarms from `DirectBootStore` (device-protected prefs). `SystemEventReceiver` on `BOOT_COMPLETED` → `reconcileAll()` + watchdog + health alert if the service isn't bound. `AlarmReceiver` is direct-boot aware and only re-arms while locked. | `ProcessStateTest.locked boot re-arms from device-protected storage` | `adb reboot`; before unlocking: `adb shell dumpsys alarm \| grep com.freezr` shows alarms; after unlocking the frozen app is blocked again. |
| 5 | App update | `MY_PACKAGE_REPLACED` → same path as boot. | `ProcessStateTest` (same plan) | `adb install -r app-debug.apk` → `dumpsys alarm` shows the alarms re-armed; frozen app still blocked. |
| 6 | Doze / App Standby / Battery Saver | `setExactAndAllowWhileIdle` (inexact `setAndAllowWhileIdle` fallback if exact alarms are revoked). Exactly two alarms (transition, pre-freeze); each re-plans on fire. No in-memory timers decide blocking. `WatchdogWorker` (15 min) runs `reconcileAll()` and alerts if broken. | `ProcessStateTest.replan arms…`, `…idempotent` | `adb shell dumpsys deviceidle force-idle`; wait past a transition; `adb shell dumpsys deviceidle unforce`; the transition happened on time (`dumpsys alarm` history). `adb shell cmd appops set com.freezr.app RUN_ANY_IN_BACKGROUND ignore` → health card warns. |
| 7 | Time / timezone / DST change | Rules are wall-clock (`TimeWindows` + `java.time` zone rules), so DST is built into each planned instant. `TIME_SET` / `TIMEZONE_CHANGED` (manifest) and `DATE_CHANGED` (registered in the service) → `reconcileAll()`. | `FreezeDecisionEngineTest` (DST gap/overlap, zone change), `ProcessStateTest.timezone change moves wall-clock transitions` | `adb shell settings put global auto_time 0`; `adb shell cmd alarm set-timezone America/New_York`; `adb shell date 1005220000` (MMDDhhmm) → `dumpsys alarm` shows re-planned times. |
| 8 | Accessibility service disabled / crashed / killed by OEM | Detected (a) on every app open (`MainActivity` → reconcile; Home re-checks `PermissionHealthChecker` in `onResume`), (b) by the watchdog, (c) on boot/update, (d) in `onDestroy` of the service. High-priority notification with a Fix action (throttled to 6 h, reset on service death). *A user Force stop cannot be prevented*; it is detected on next open. | — | `adb shell settings put secure enabled_accessibility_services ""` → notification "Freezr can't freeze apps" appears and the Home health card shows the fix. |
| 9 | Permission revoked at runtime | Each feature checks at use time and degrades: no usage access → empty usage (limits inactive); no notification permission → silent; no exact alarms → inexact; no location → place/Wi-Fi rules forced inactive. All surface in the health card. | `ProcessStateTest` (alarms without exact permission still scheduled) | `adb shell appops set com.freezr.app GET_USAGE_STATS ignore`, `adb shell pm revoke com.freezr.app android.permission.POST_NOTIFICATIONS` → no crash; health card lists both. |
| 10 | Screen off / locked / multi-user / work profile | Screen off folds the live usage delta and stops the limit ticker; `SCREEN_ON`/`USER_PRESENT` reconcile usage and re-scan windows. The keyguard and System UI are never treated as the foreground app. All state is per-user (Android sandbox); work-profile apps are listed by the profile's own launcher query and are separate packages per user. | — | Lock with the frozen app open, unlock → overlay is shown again. Create a second user (`adb shell pm create-user test`), switch → no crash; Freezr is independent per user. |
| 11 | Concurrent edits during a freeze | Schedule + package set written in one `@Transaction`; `loadFresh()` reads every table inside one transaction. `StrictGuard` rejects loosening edits at the data layer, so no UI path (tile, widget, notification) can bypass it. | `RepositoriesTest.strict mode blocks loosening edits…`, `DaoTest` | Enable Strict Mode during a schedule; try to disable it from the app, tile and notification → all refused. |
| 12 | Data migration | Room v1 → v2 (`MIGRATION_1_2`, adds context rules and blocked domains). Schemas exported in `app/schemas`. | `MigrationTest` (validates against `2.json`, data preserved) | Install a v1 build, add data, install current build → data intact. |

## Useful commands

```bash
adb shell dumpsys alarm | grep -A3 com.freezr.app          # planned transitions
adb shell dumpsys accessibility | grep -i freezr            # service bound?
adb shell dumpsys jobscheduler | grep -A2 com.freezr.app   # WorkManager watchdog job
adb shell cmd deviceidle force-idle / unforce
adb shell am force-stop com.freezr.app                      # disables the service until next open (expected)
```
